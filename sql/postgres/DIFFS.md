# Postgres SQL reference vs live Neon (`lorebot-prd`)

Repo files under `sql/postgres/` are documentation/AI references. The app does **not** apply them; Neon already has the live schema/functions.

Compared against Neon project `lorebot-prd` / database `neondb` / schema `lorebot` (inspected via Neon MCP).

## Cross-cutting differences (repo Postgres vs Neon)

| Topic | Live Neon | `sql/postgres/` in this repo |
| --- | --- | --- |
| Unique key for lore upserts | **No** unique index on `lore.object_name` (only PK on `lore_id`) | Adds `lore_object_name_uidx` so `ON CONFLICT (object_name)` is valid |
| Unique key for person upserts | **No** unique index on `person.charname` (only PK on `person_id`) | Adds `person_charname_uidx` so `ON CONFLICT (charname)` is valid |
| `varchar` lengths | Mostly unconstrained `character varying` | Lengths aligned with legacy MySQL (`varchar(100)`, etc.) |
| ID columns | `bigint` + sequences (`nextval('lore_lore_id_seq')`) | `GENERATED BY DEFAULT AS IDENTITY` (equivalent intent) |
| Timestamps | `timestamptz` | `timestamptz` |
| Function names | Mixed-case quoted (`"CreateLore_v002"`) | Same quoted names |
| Upsert style | `INSERT … ON CONFLICT … DO UPDATE` | Same |
| Schema qualification in function bodies | Often unqualified `"lore"` / `"person"` (relies on search_path) | Prefer `lorebot.lore` / `lorebot.person` for clarity |
| Identifier quoting in function bodies | Heavy double-quoting of lowercase names | Mostly unquoted lowercase (same after fold) |

**Important Neon risk:** live `"CreateLore*"`` / `"CreatePerson_v002"` use `ON CONFLICT ("object_name")` / `ON CONFLICT ("charname")`, but Neon currently has **no** matching unique constraints. Those upserts can error at runtime until unique indexes are added. The repo DDL includes those indexes on purpose.

## Per-object notes

### `create_db.sql`
- Neon has tables `lorebot.lore` and `lorebot.person` with PK indexes named like `idx_24578_primary` (migration leftovers).
- Neon `person.create_date` has **no** `DEFAULT now()` in catalog (column default null); MySQL had `DEFAULT CURRENT_TIMESTAMP`. Repo DDL sets `DEFAULT now()`.
- Neon lacks unique indexes on `object_name` / `charname` (see above).
- Neon has no separate checked-in DDL file; this file is reconstructive.

### `CreateLore_v002.sql` / `CreateLore.sql`
- Logic matches Neon: upsert on `object_name`, updates `create_date` to `NOW()`, maps `p_weapclass` → `class`.
- Neon body uses mixed-case param refs (`p_objName`) which fold to lowercase in PL/pgSQL; repo uses consistent lowercase (`p_objname`).
- Neon quotes every column (`"object_name"`); repo uses unquoted lowercase.
- Same as Neon: returns `void` (app looks up `lore_id` after call).

### `CreatePerson_v002.sql`
- Matches Neon arg list (`p_weap1`/`p_weap2` → `primary_weap`/`secondary_weap`, `p_onchest` → `on_chest`).
- Same `ON CONFLICT (charname)` upsert pattern (needs unique index; Neon missing it).

### `CreatePerson.sql`
- **Not present on Neon.** Only `"CreatePerson_v002"` exists live.
- Repo file is a Postgres port of the legacy MySQL proc (no `on_chest`) for docs parity with `sql/mysql/CreatePerson.sql`.

### `GetRecent.sql`
- Matches Neon: `UNION ALL` of 15 latest persons + 15 latest lore, outer `ORDER BY "CREATE_DATE" DESC`.
- Return columns match Neon: `"TBL_SRC"`, `"DESCRIPTION"`, `"CREATE_DATE"`, `submitter` (lowercase).
- MySQL used `UNION` (dedupe); Neon/repo use `UNION ALL`.

### `GetPerson.sql`
- Matches Neon: `RETURNS SETOF person`, filter on `charname`.
- Neon body uses `p_charName` (folds to `p_charname`); repo uses `p_charname`.

### `GetPersonList.sql`
- Matches Neon return shape: `"CHARNAME"`, `submitter`, `"Create_DATE"` (mixed-case aliases preserved for GraphQL-ish consumers).
- Neon qualifies `lorebot."person"`; repo uses `lorebot.person`.

### `GetLoreCount.sql`
- Neon live body is:
  `SELECT COUNT(*) FROM "lore";`
  inside `RETURNS TABLE("LoreCount" bigint)` **without** an `AS "LoreCount"` alias.
- Repo version adds `COUNT(*)::bigint AS "LoreCount"` so the output column name is explicit/correct.

## MySQL → Postgres changes (vs `sql/mysql/`, for context)

These apply to all ports and are intentional dialect changes, not Neon diffs:

- `DELIMITER` / `CREATE PROCEDURE` / `DEFINER` → `CREATE FUNCTION … LANGUAGE plpgsql`
- Backticks → lowercase unquoted (or quoted mixed-case only where Neon does)
- `IF EXISTS … UPDATE ELSE INSERT` → `INSERT … ON CONFLICT DO UPDATE`
- `UPDATE … LIMIT 1` removed (unsupported in Postgres)
- `ENGINE=InnoDB`, `AUTO_INCREMENT`, `CHARSET=latin1` → identity/`bigint`/`timestamptz`
