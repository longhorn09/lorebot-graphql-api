# Postgres SQL reference vs live Neon (`lorebot-prd`)

Repo files under `sql/postgres/` are documentation/AI references. The app does **not** apply them; Neon already has the live schema/functions.

Compared against Neon project `lorebot-prd` / database `neondb` / schema `lorebot` (inspected via Neon MCP).

## Cross-cutting differences (repo Postgres vs Neon)

| Topic | Live Neon | `sql/postgres/` in this repo |
| --- | --- | --- |
| Unique key for lore upserts | Has `lore_object_name_uidx` on `lore.object_name` (applied 2026-08-08; also PK on `lore_id`) | Same: `lore_object_name_uidx` for `ON CONFLICT (object_name)` |
| Unique key for person upserts | Has `person_charname_uidx` on `person.charname` (applied 2026-08-08; also PK on `person_id`) | Same: `person_charname_uidx` for `ON CONFLICT (charname)` |
| `varchar` lengths | Mostly unconstrained `character varying` | Lengths aligned with legacy MySQL (`varchar(100)`, etc.) |
| ID columns | `bigint` + sequences (`nextval('lore_lore_id_seq')`) | `GENERATED BY DEFAULT AS IDENTITY` (equivalent intent) |
| Timestamps | `timestamptz` | `timestamptz` |
| Function names | Mixed-case quoted (`"CreateLore_v002"`) | Same quoted names |
| Upsert style | `INSERT … ON CONFLICT … DO UPDATE` | Same |
| Schema qualification in function bodies | Often unqualified `"lore"` / `"person"` (relies on search_path) | Prefer `lorebot.lore` / `lorebot.person` for clarity |
| Identifier quoting in function bodies | Heavy double-quoting of lowercase names | Mostly unquoted lowercase (same after fold) |

**Upsert unique indexes (applied 2026-08-08):** Neon now has both `lore_object_name_uidx` (after deleting 5 exact duplicate `object_name` pairs) and `person_charname_uidx` (no duplicates found). `"CreateLore_v002"` / `"CreatePerson_v002"` `ON CONFLICT` upserts should no longer fail with `42P10`. Legacy `"CreatePerson"` was never on Neon; legacy `"CreateLore"` was dropped 2026-08-08 (app only calls `_v002`).

## Per-object notes

### `create_db.sql`
- Neon has tables `lorebot.lore` and `lorebot.person` with PK indexes named like `idx_24578_primary` (migration leftovers).
- Neon `lore.create_date` and `person.create_date` both have `DEFAULT now()` (applied 2026-08-08; matches MySQL `DEFAULT CURRENT_TIMESTAMP` / repo DDL).
- Neon has both `lore_object_name_uidx` and `person_charname_uidx` (aligned with this file as of 2026-08-08).
- Neon has no separate checked-in DDL file; this file is reconstructive.

### `CreateLore_v002.sql`
- Logic matches Neon: upsert on `object_name`, updates `create_date` to `NOW()`, maps `p_weapclass` → `class`.
- Neon `ON CONFLICT ("object_name")` is valid via live `lore_object_name_uidx`.
- Neon body uses mixed-case param refs (`p_objName`) which fold to lowercase in PL/pgSQL; repo uses consistent lowercase (`p_objname`).
- Neon quotes every column (`"object_name"`); repo uses unquoted lowercase.
- Same as Neon: returns `void` (app looks up `lore_id` after call).
- Legacy `"CreateLore"` (no `can_use`) removed from Neon and repo; only `_v002` remains.

### `CreatePerson_v002.sql`
- Matches Neon arg list (`p_weap1`/`p_weap2` → `primary_weap`/`secondary_weap`, `p_onchest` → `on_chest`).
- Neon `ON CONFLICT ("charname")` is valid via live `person_charname_uidx`.
- Proper-cases `charname` on write (`upper(left(...)) || lower(substring(...))`, e.g. `nooka` → `Nooka`); GraphQL resolver also applies `proper()` before call. Person searches use `LOWER(charname) = LOWER(?)` so `nooka` / `Nooka` hit the same row.

### `GetRecent.sql`
- Matches Neon: `UNION ALL` of 15 latest persons + 15 latest lore, outer `ORDER BY "CREATE_DATE" DESC`.
- Return columns match Neon: `"TBL_SRC"`, `"DESCRIPTION"`, `"CREATE_DATE"`, `submitter` (lowercase).

### `GetPerson.sql` / `GetPersonList.sql` / `GetLoreCount.sql`
- Present on Neon and in this folder for reference, but **not called by this GraphQL API** (resolvers use inline SQL / counts instead).
- `GetLoreCount` Neon body is `SELECT COUNT(*) FROM "lore"` inside `RETURNS TABLE("LoreCount" bigint)` without an explicit `AS "LoreCount"` alias; repo SQL adds the alias.
